# Subscription & Feed Reference

All URLs below use the stable raw base:

```text
https://raw.githubusercontent.com/Mohamadhosein76/auto-subscription-engine/main/public/
```

Feed files are promoted only after verification and guarded publication. A path listed as **conditional** may be absent when the current run lacks the evidence required to publish it.

## Backward-compatible subscriptions

| Path | Format | Contract |
|---|---|---|
| `subscription.txt` | UTF-8 share URIs | main legacy subscription; byte-equal to the universal URI feed after successful Stage-10+ publication |
| `subscription_base64.txt` | Base64 | exact Base64 encoding of `subscription.txt` |
| `best.txt` | UTF-8 share URIs | bounded selected LIVE subset from the legacy publication contract |
| `countries/<CC>.txt` | UTF-8 share URIs | country-specific LIVE output when present |

## Client feeds

| Path | Evidence | Format |
|---|---|---|
| `clients/universal.txt` | verified universal/all-applicable-core intersection | share URIs |
| `clients/v2rayng.txt` | Xray PASS + client score policy | share URIs |
| `clients/v2rayng_base64.txt` | exact Base64 companion when published | Base64 |
| `clients/hiddify.txt` | Hiddify-Core PASS + client score policy | share URIs |
| `clients/hiddify_base64.txt` | exact Base64 companion when published | Base64 |
| `clients/nekobox.txt` | sing-box PASS + client score policy | share URIs |
| `clients/nekobox_base64.txt` | exact Base64 companion when published | Base64 |
| `clients/singbox.json` | sing-box PASS + client score policy | native sing-box JSON |
| `clients/mihomo.yaml` | Mihomo PASS + client score policy | native Mihomo YAML |
| `clients/manifest.json` | safe counts/core availability | credential-free JSON |

Runtime-core evidence is not the same as a manual GUI/device certification. See `ARCHITECTURE.md` for that boundary.

## Quality profiles

Generated by the central Feed Engine:

- `profiles/recommended.txt` — universal nodes meeting the recommended global score, with verified universal fallback if the pool is too small.
- `profiles/secure.txt` — candidates meeting both global and Security score thresholds.
- `profiles/max-compat.txt` — broad verified LIVE pool ranked by global quality.

Each text feed receives an exact `_base64.txt` companion.

## Network feeds

Generated from measured/canonical network traits:

- `networks/direct-ip.txt`
- `networks/ipv4.txt`
- `networks/ipv6.txt`
- `networks/tcp.txt`
- `networks/udp.txt`
- `networks/port443.txt`
- `networks/mobile-safe.txt`

Each text feed receives an exact Base64 companion. `mobile-safe` is a conservative heuristic candidate profile, **not** an MCI/Irancell/Rightel/fixed-network guarantee.

## Operator feeds — conditional on fresh evidence

For each configured operator dimension, ASE writes a safe manifest. Credential-bearing operator subscriptions are emitted only when current operator evidence satisfies score, confidence, freshness and client/core requirements.

Example paths after fresh MCI evidence exists:

```text
operators/mci/manifest.json
operators/mci/v2rayng.txt
operators/mci/hiddify.txt
operators/mci/nekobox.txt
operators/mci/singbox.json
operators/mci/mihomo.yaml
operators/mci/universal.txt
```

The same pattern applies to `irancell`, `rightel`, `fixed` and configured custom profiles. If current evidence is insufficient/stale, ASE does not preserve an old operator credential feed as though it were current.
